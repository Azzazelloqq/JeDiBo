# JeDiBo — прототип «Классика»

Тактическая дуэль 12×12 с Картами Кармы. Визуал — программный пиксель-арт в духе Balatro,
стилистика — брутализм (бетон, базальт, красный гранит) из 3D-прототипа.

**Windows:** двойной клик по `start.bat` — сам поставит зависимости и откроет игру.

```
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build в dist/
npm run sim -- 200 # headless: 200 партий бот-против-бота, проверка движка
```

Каждый пуш в `main` собирается и публикуется на GitHub Pages (`.github/workflows/pages.yml`).

Без фреймворков и ассетов: TypeScript + Vite, всё (фигуры, плиты, карты, логотип, звук) генерируется кодом.

## Что есть

- **Правила Классики целиком** (ГДД): поле, фигуры, ОД, атака, повышение (в т.ч. отложенное под атакой),
  таймеры 5/60 мин, автозавершение хода, ничья по составу, победа/сдача.
- **Все 21 Карта Кармы** (34 в общей колоде, 21 случайная в матче), цикл 7 ходов, периоды, «занимает ход».
- Режимы: против бота «Странник», хотсит со скрытой расстановкой. «По сети» — заглушка, архитектура готова.
- Мини-профиль: имя, аватар-идентикон, рейтинг Эло (против бота), звания, статистика, история.
- Экраны: меню, расстановка (пресеты), партия, оверлей Кармы, итог, колода, правила, профиль, настройки.

## Архитектура

```
src/
  core/            ← чистая логика, без DOM. Детерминирована: seed + ГСЧ в состоянии.
    types.ts         GameState, Action, GameEvent — всё сериализуемо (JSON)
    rules.ts         геометрия, генерация ходов, атаки, модификаторы Кармы
    ops.ts           мутации + события (destroy/spawn/setRank/ask/promotion)
    engine.ts        createGame() / dispatch(state, action) → { ok, events }
    karma/cards.ts   реестр карт: данные + обработчики play/onChoice
    modes.ts         ModeConfig (Классика); новый режим = новый объект
    presets.ts       пресеты расстановки
  ai/bot.ts        жадный бот, одно действие за вызов
  session/match.ts Match: контроллеры (human/bot/remote), очередь действий, часы
  net/transport.ts интерфейс Transport + stateHash() для p2p lockstep
  render/          пиксель-арт и анимации (canvas), фон-шейдер (WebGL), сок (тряска, баннеры)
  audio/sfx.ts     синтез звуков на WebAudio
  profile/         профиль и настройки в localStorage
  ui/              экраны и виджеты на чистом DOM
```

### Поток действия

```
UI-клик / бот / сеть ─► Match.submit(action)
                         └► engine.dispatch(state, action)  ── валидация, мутация, события
                              └► Match.onEvents(events)     ── UI проигрывает анимации по очереди
                                   └► следующее действие из очереди / ход бота
```

Движок не знает о времени и DOM, UI не меняет состояние напрямую — только через `Action`.

### Вопросы игроку (выбор целей)

Любая карта, требующая выбора, ставит `state.pending` — одиночный вопрос (клетка или запись кладбища)
с `chooser` (кто отвечает: может быть и соперник — «Двойная смерть», «Девальвация», «Предательство»),
списком допустимых `options` и флагом `canSkip`. Многошаговые карты задают вопросы последовательно
(`step`, `data`). Несколько вопросов подряд — `state.queue`. Повышение использует тот же механизм.

Это даёт единый UX («подсвеченные клетки + подсказка внизу») и единый путь для бота и сети.

### Как добавить карту

1. id в `CardId` (`core/types.ts`);
2. запись в `defs` (`core/karma/cards.ts`): `play`, при необходимости `onChoice` / `canPlay`.
   Для «выберите N фигур» есть `pickPieces()`, для смены ранга — `rankShift()`;
3. иконка 14×14 в `ICONS` (`render/cardArt.ts`) — ASCII, контур дорисуется автоматически;
4. если появляется новый длящийся эффект — вариант в `Effect` и его учёт в `rules.ts`.

### P2P (следующий шаг)

Lockstep: пиры обмениваются `seed` и потоком `Action` (`NetMessage`), каждый гоняет тот же
`dispatch`. `stateHash()` после каждого действия ловит рассинхрон. Нужно:
`WebRTCTransport implements Transport`, контроллер `'remote'` в `Match` (входящие действия → `submit`),
сигналинг (обмен SDP) и скрытая расстановка (commit-reveal: сначала хэш расстановки, потом сама).
Часы для сети стоит передавать в `Action` (`timeout` уже действие движка).

## Визуальная система

Две темы × две поверхности (Настройки → «Тема» / «Поверхность», или `?theme=dark|light&surface=stone|flat`):
тёмная — исходный бруталистский дизайн, светлая — красный акцент на тёплом светлом камне; «Камень» — с фактурами
и фасками, «Плоская» — без рельефа. Ниже — описание светлой темы; роли токенов в обеих одинаковые.

«Дневной бетон»: брутализм остаётся (литой бетон, опалубка, гранит и графит фигур, жёсткие тени, «сок»),
но без мрака — светлые бетонные плиты на тёплом сером фоне, акцент — фирменный оранжевый логотипа.

- **Палитра** — `render/palette.ts` (единый источник, прокидывается в CSS-переменные `--slab-900` и т.п.),
  токены названы по роли:
  `void/ink` — тёплый графит (контуры, тени, текст на светлом) · `slab900…500` — базальт (рамы, поле,
  «утопленные» поверхности) · `concrete600…100` — бетон (панели ≈ `concrete300`, кнопки ≈ `concrete200`) ·
  `bone` — светлый текст · `brand800…100` — фирменный оранжевый, `brand500 = #FF3600` (главное действие,
  выделение, акцентные квадраты) · `granite900…400` — гранит красных фигур (только фигуры и красная сторона) ·
  `amber*` — Карма · `bronze500` — редкие карты · `patina*` — инфо / «хорошо».
  Контраст: текст `void` на `concrete300` ≈ 9:1, приглушённый `slab700` на `concrete300` ≈ 5:1.
- **Поверхности** — `.slab` светлая бетонная плита с графитовым текстом; `.inset`/статистика/лог/счётчики —
  тёмный базальт с текстом `bone`. Кнопки: `btn-stone` (по умолчанию), `btn-brand` (главное действие),
  `btn-amber` (Карма), `btn-dark`.
- **Логотип** — `src/assets/logo/*.svg` (знак на сетке 7×7 модулей + надпись «JE DI BO», трассировка гайда),
  `logoEl()` в `ui/widgets.ts`; пиксельный знак `logoMark(k)` в `render/sprites.ts` — рубашка карт и favicon.
- **Поле** — канвас 212×212, целочисленный масштаб: светлые литые бетонные плиты с порами и фасками,
  базальтовая рама со стяжками опалубки, координаты пиксельным шрифтом 3×5.
- **Фигуры** — гранит (красные) и графит (чёрные): верхняя грань + 3 px «толщины», свет слева-сверху,
  крапинки, контур. Направление треугольника = направление «вперёд» владельца.
- **Карты** — плита по тиру (простая — светлый бетон, редкая — бронза, роковая — оранжевый гранит),
  утопленное окно с иконкой, лёгкий 3D-наклон, пиксельный блик (полоса + кромка + искры, в разрешении карты,
  не ложится на название), «дыхание», переворот. Рубашка — пиксельный знак на бетоне.
- **Сок**: прыжок фигуры со сквошем и пылью, рывок атаки + разлёт каменных осколков + тряска,
  падение новых фигур с отскоком, луч «Линии смерти», барьер-блоки с предупреждающими полосами,
  баннеры ходов, всплывающий урон, поп чисел, штамп названия карты, тонкие ЭЛТ-сканлайны,
  закрученный фон-шейдер, меняющий «настроение» (меню / партия / Карма / победа / поражение);
  `setBackgroundPalette()` задаёт свои цвета или плавный цикл.
- **Шрифты**: Tiny5 (пиксельный, с нормальной кириллицей), IBM Plex Mono (текст).
