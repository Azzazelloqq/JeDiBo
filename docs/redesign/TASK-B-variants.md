# Задача B — свитчер визуала и варианты экранов

**Цель:** собрать в игре переключатель визуала, через который владелец сравнивает несколько вариантов UI для каждого экрана, плюс пиксельные иллюстрации Карт Кармы с переключателем в Колоде.

Сначала прочитай `docs/redesign/README.md` (словарь вариантов а/б/в, правила, **владение файлами** и порядок относительно задачи A), загрузи скиллы `jedibo-ui` и `jedibo-pixel-art`. Вариант «а» опирается на дизайн-токены задачи A — бери их из `docs/redesign/HANDOFF.md`, который A оставит при завершении.

## Порядок

Задача B стартует **после того, как владелец утвердил дизайн A и он влит в ветку `redesign`**. Начни с `docs/redesign/HANDOFF.md`. Вариант «в» = утверждённый дизайн A: не меняй его вид, только подключай к свитчеру.

| Этап | Что |
|---|---|
| B1 | Инфраструктура свитчера |
| B2 | Пиксельные иллюстрации карт (скрипт + ассеты) и режим «Иллюстрации» |
| B3 | Эмблемы и расширенная история для Летописи |
| B4 | Варианты «б» (1:1 с референсом) всех экранов |

| B7 | Партия: вариант «а» |
| B8 | Правила: анимированные примеры |

## B1. Свитчер

**Модель.**
```ts
// src/ui/variants/registry.ts
export type VariantId = 'a' | 'b' | 'c';            // а — Референс·наш стиль, б — Референс 1:1, в — Текущий
export type ScreenId = 'menu' | 'modeSelect' | 'chronicle' | 'codex' | 'rules' | 'settings' | 'game';
export const AVAILABLE: Record<ScreenId, VariantId[]> = {
  menu: ['a', 'b', 'c'], modeSelect: ['a', 'b'], chronicle: ['a', 'b', 'c'],
  codex: ['a', 'b', 'c'], rules: ['a', 'b', 'c'], settings: ['a', 'b', 'c'], game: ['a', 'c'],
};
export function variantOf(s: ScreenId): VariantId;   // с откатом на первый доступный
export function setVariant(s: ScreenId | 'all', v: VariantId): void;
export function screen(s: ScreenId): Screen;         // фабрика: вернёт экран нужного варианта
export const cardArtMode: () => 'icons' | 'illustrated';
export function setCardArtMode(m): void;
```
- Хранение: `localStorage['jedibo.ui.v1']` (через try/catch, как в `profile.ts`). URL-переопределение для ссылок на сравнение: `?ui=b` (всё) или `?ui=menu:a,codex:b`.
- На `<body>` класс темы текущего экрана: `ui-a` / `ui-b` / `ui-c` — стили вариантов скоупятся по нему (`src/styles/variants/a.css`, `b.css`), чтобы не пересекаться с `main.css`.
- Смена варианта перерисовывает текущий экран на месте (без потери состояния партии там, где это возможно; для `game` — допустимо применять со следующей партии и показать тост).
- `modeSelect` в варианте «в» не существует: в «в» меню само содержит плитки режимов (как сейчас).

**UI свитчера.** Плавающая пиксельная плашка в левом нижнем углу «ВИЗУАЛ ▸» поверх всех экранов (z-index выше `#crt`), горячая клавиша `F2` (не `V`: буквы могут понадобиться в партии). Панель:
- строка «Все экраны: [А] [Б] [В]»;
- по строке на экран с доступными буквами, недоступные — не показывать;
- «Карты Кармы: [Иконки] [Иллюстрации]»;
- «Скрыть плашку» (возвращается по `F2`).
Стиль панели — нейтральный «служебный» (моноширинный текст, тёмная подложка), одинаковый во всех вариантах, чтобы не путать с тестируемым UI.

## B2. Иллюстрации Карт Кармы в пиксель-арте

Исходники: `docs/redesign/assets/card-illustrations/<cardId>.jpg` (512×768, имена = `CardId`). Проба: `assets/card-pixel-test-40x60-48x72.png` — 48×72 и палитра 10 цветов уже читаются. Процесс и правила — в скилле `jedibo-pixel-art` (раздел «Иллюстрации карт»).

1. Скрипт `scripts/pixelize-cards.(ts|py)` — воспроизводимый, параметры в одном месте: таблица кадрирования по карте (центр интереса + масштаб, чтобы фигура/жест были крупно), размер выхода = внутреннее окно карты (см. ниже), палитра из `render/palette.ts` после A (бренд-оранжевый, 2–3 оранжевых, графит, 3–4 бетонных серых, `bone`), квантование без дизеринга или с упорядоченным 2×2 только в полутонах, удаление одиночных пикселей-соринок, опционально 1-px контур `ink` у тёмных силуэтов.
2. Выход: `public/cards/pixel/<cardId>.png` (коммитятся). Скрипт запускается вручную, не в `build`.
3. Лицевая сторона карты в режиме «Иллюстрации» (`ui/card.ts`, `render/cardArt.ts`; к этому моменту дизайн A уже утверждён): рамка-плита по тиру 2 px карты, иллюстрация на всё внутреннее поле, плашка названия поверх нижней трети (как сейчас), строка тира под ней. Размер карты остаётся 52×72 → окно иллюстрации 48×68 (или иное целое, согласованное с рамкой). Блик — тот, что сделал A (A6), проверить, что не мешает чтению на светлых иллюстрациях.
4. Переключатель: глобальный `cardArtMode` (B1). Видимая кнопка — в Колоде во всех вариантах (в «б» — на месте «РЕДАКЦИЯ: РЕЙТИНГ» справа внизу: «КАРТЫ: ИЛЛЮСТРАЦИИ / ИКОНКИ»). Режим действует везде, где рисуется `cardEl` (колода, рука, оверлей Кармы).
5. Проверить все 21 карту при scale 2, 3, 4. Если какая-то читается плохо — поправить кадр в таблице, при необходимости вручную подчистить PNG (фиксировать это в README скрипта).

## B3. Летопись: эмблемы и расширенная история

«Летопись» заменяет «Профиль» (в варианте «в» остаётся текущий «Профиль», переименованный в «Летопись» в кнопке меню).

**Данные** — `src/profile/emblems.ts` (новый, B):
- В `MatchRecord` добавить (необязательные, старые записи без них — валидны): `ownTurns`, `karmaReceived`, `piecesLost`, `piecesTotal` (21), `promotions`, `cardsPlayed`, `opponent`, `kind`, `mode: 'classic'`. Заполнять в `game.ts → showResult`.
- Эмблемы: `{ id, name, desc, tier: 'знак'|'печать'|'клеймо', points: 1|2|3, check(rec, profile) }`, состояние `unlocked: Record<id, timestamp>` в профиле. Проверка — после каждой партии, тост «Новая эмблема».
- Набор для Классики (не копировать эмблемы чужих режимов):

| Эмблема | Условие | Тир |
|---|---|---|
| Первый камень | Выиграть первую партию | знак |
| Странник ошибся | Выиграть у Странника (бот) | знак |
| Двое за столом | Доиграть партию за одним компьютером | знак |
| Равновесие | Довести партию до ничьей | печать |
| Безупречная кладка | Выиграть, не потеряв ни одной фигуры | клеймо |
| Последний камень | Выиграть, когда у вас осталась одна фигура | клеймо |
| Долгая стройка | Выиграть партию длиннее 40 ваших ходов | знак |
| Снос | Выиграть быстрее чем за 15 ваших ходов | печать |
| Шесть знаков | Получить Карму 6 раз за партию | печать |
| Карьерист | Повысить фигуры 3 раза за партию | печать |
| До круга | Довести треугольник до круга двумя повышениями | клеймо |
| Роковая ставка | Выиграть партию, разыграв роковую карту | знак |

Если какое-то условие нельзя надёжно посчитать из событий движка — замени близким и отметь в HANDOFF.

- Иконки эмблем — пиксельные спрайты 16×16 кодом (ASCII, как `ICONS` в `cardArt.ts`), закрытые — затемнённый силуэт (как на `refs/04`).
- Шапка Летописи: звание по рейтингу (`TITLES`: Щебень → Монолит) + описание звания, «ЭМБЛЕМ n / N · ОЧКОВ m», сегментированная полоса до следующего звания, аватар и редактируемое имя (функциональность профиля не теряем), рейтинг. Статистика из профиля — компактной строкой в шапке или под вкладками.
- Строка истории (как `refs/03`): «КЛАССИКА · ПРОТИВ СТРАННИКА · ПОБЕДА», «ваших ходов N · Карма приходила N раз · потеряно фигур N из 21 · соперник: …», дата «сегодня / вчера / 12 окт», цвет строки по исходу (победа — патина, поражение — красноватый, ничья — нейтральный), изменение рейтинга справа.

### Правила (`refs/07`) — а, б, в
UX по рефу: слева список разделов, справа прокручиваемый текст; колесо листает, раздел слева подсвечивается по прокрутке (scrollspy), клик по разделу — плавная прокрутка. Каждый пункт — карточка «мини-доска с анимированным примером + крупная формулировка», под ней пояснение.
Разделы для Классики: Поле и армия · Ход и очки действий · Фигуры и взятие · Повышение · Карма · Победа и ничья · Время · Режимы (бот / один ПК / сеть) · Словарь. Текст брать из текущего `rules.ts` и описаний карт, не выдумывать механику.
Анимированные примеры (B8) — **в стиле нашего геймплея во всех вариантах** (наши плиты поля, наши фигуры, наши эффекты из `render/`): мини-поле 4×4…6×6 на canvas, скрипт шагов в цикле:
- поле 12×12 и зоны расстановки (подсветка трёх своих рядов);
- треугольник: шаг вперёд; квадрат: 1–3 вперёд/вбок/по диагонали; круг: до 5 в любую сторону, блокировка промежуточной клеткой;
- атака: рывок, осколки, «сгорают» оставшиеся очки действий (пипы гаснут);
- 5 очков действий: пипы тратятся по одному;
- повышение: дошёл до последнего ряда → вспышка → квадрат появляется в стартовой зоне; отложенное повышение под атакой;
- Карма: трек 7 ходов заполняется → карта вылетает и переворачивается;
- ничья: две одинаковые фигуры, счётчик трёх периодов.
Движок примера: `src/ui/variants/rulesDemo.ts` — таймлайн шагов поверх `pieceSprite`/`cellTile`/`fx`, без настоящего `Match`. Пауза вне экрана (`IntersectionObserver`), при `prefers-reduced-motion` — статичный финальный кадр со стрелкой. Скорость учитывает настройку «Скорость анимаций».
- **б:** панели и навигация 1:1 по рефу, примеры — наш геймплейный стиль.
- **в:** текущие «Правила» (после A).

### Партия (`refs/09`, идеи HUD — `refs/10`) — а, в
