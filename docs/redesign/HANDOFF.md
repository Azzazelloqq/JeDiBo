# Передача: задача A → задача B

Задача A (переработка визуала, «Дневной бетон») сделана в ветке `req/redesign-a-49cf2f` (от `redesign`).
**Статус: ждёт утверждения владельцем.** Пока владелец не утвердил и A не влита в `redesign`, задачу B не начинать.
Скриншоты: `docs/redesign/result/A/` — `before/` и `after/` (1440×900), `after-1920/`, `compare/` (до | после).

Что это значит для B: вариант **«в» (Текущий)** во всех экранах — это то, что сейчас лежит в `src/ui/screens/*`.
Его не переделывать, только подключить к свитчеру. Вариант **«а»** строится на токенах и компонентах ниже.

> **Обновление (решение владельца):** две темы, вариант поверхности выбран.
> - Тёмная (`theme=dark`, по умолчанию) — исходный дизайн из `main` (`src/styles/dark.css`).
> - Светлая (`theme=light`) — красный акцент на тёплом светлом камне (`src/styles/light.css`); фон партии — контрастный,
>   с красноватыми тенями и красным дымом.
> - UI в обеих темах рельефный (фактуры, фаски). Клетки поля плоские (ровная заливка, тонкий шов) в обеих темах;
>   рама доски и фигуры — рельефные. Плоский режим UI (`surface=flat`) по решению владельца удалён.
> - Выбор темы: Настройки → «Тема» (сохраняется, страница перезагружается) или `?theme=…` в адресе.
>   Палитры `DARK`/`LIGHT` и `THEME` — в `render/palette.ts`; тема фиксируется при загрузке, до генерации спрайтов.
> - Цвет логотипа — токен `logo` (#FF3600) в обеих темах. Таблица токенов ниже описывает светлую тему;
>   роли токенов в тёмной те же (`brand*` = исходные красные/«сигнал», `granite*` = исходные `blood*`).

## 1. Токены (единственный источник — `src/render/palette.ts`)

В CSS они доступны как переменные: `slab900` → `--slab-900`, `brand500` → `--brand-500`. Hex в CSS/TS не писать.

| Роль | Токены | Где использовать |
|---|---|---|
| самое тёмное | `void`, `ink` | контуры, жёсткие тени, текст на светлом |
| базальт | `slab900…500` | рамы, поле, «утопленные» поверхности, тёмные кнопки |
| бетон | `concrete600…100` | панели (≈ `concrete300`), кнопки (≈ `concrete200`) |
| светлый | `bone` | текст на тёмном, блики |
| **бренд** | `brand800 / 700 / 500 / 400 / 100` | акцент UI, главное действие, выделение. `brand500 = #FF3600` — цвет логотипа |
| гранит | `granite900…400` | только красные фигуры и «красная сторона» (чипы, лог, эффекты) |
| Карма | `amber700 / 500 / 300 / 100` | всё про Карму |
| бронза | `bronze500` | плита редких карт |
| инфо | `patina700 / 500 / 300` | «хорошо», часы, защита |

Фигуры: `STONE.red` (гранит) и `STONE.black` (графит) в той же палитре.

Семантические CSS-переменные (`:root` в `src/styles/main.css`): `--shade` (полупрозрачная тень из `void`), `--edge`,
`--panel-text`, `--panel-muted`, `--inset-text`, `--inset-muted`, `--muted` (переопределяется контекстом:
на фоне — светлый, внутри `.slab` — `slab700`, внутри базальта — `concrete400`).
Фактуры бетона: `--tex-concrete` (`concrete300`), `--tex-concrete-light` (`concrete200`), `--tex-slab` (`slab800`), `--tex-slab-light` (`slab700`).

Контраст: `void` на `concrete300` ≈ 9:1; `slab700` на `concrete300` ≈ 5:1; `bone` на `brand700` ≈ 5.7:1.
`bone` на `brand500` — только крупный текст (≈ 3.4:1), поэтому у `btn-brand` тень `brand800`.

## 2. Компоненты (CSS-классы)

- `.slab` — светлая бетонная плита: графитовый текст, стяжки опалубки, жёсткая тень `--edge`.
- `.inset` — тёмный базальт с текстом `bone` (вложенные поверхности). Так же уже оформлены `.stat`, `.hist`, `.effect`, `.log-list`, `.meter`, `.pip`, `.kt`.
- Кнопки — только через `btn(label, onClick, cls)`: `btn-stone` (по умолчанию), `btn-brand` (главное действие; бывший `btn-red`), `btn-amber` (Карма), `btn-dark`; размеры `btn-small` / `btn-big`. Покачивание `--wob` уменьшено вдвое.
- `.h-label` — подпись секции с квадратом `brand500`.
- `.page-head h1` — заголовок страницы: `bone`, тень графитом, квадрат бренда слева.
- `.tag` — сплошные ярлыки, читаются и на бетоне, и на тёмном оверлее: `.tag-brand`, `.tag-tier-simple|rare|fatal`.
- Тосты `toast(text, 'stone' | 'brand' | 'amber')`, баннеры `banner(text, sub, 'brand' | 'amber' | 'stone')` (тон `red` переименован в `brand`).
- Оверлеи: `.overlay` (затемнение `slab900`, не чёрное), `.karma-overlay` (янтарь), `.result-overlay`, `.dialog`.

## 3. API для варианта «а»

| Что | Где | Как |
|---|---|---|
| Логотип | `ui/widgets.ts` | `logoEl({ variant: 'full' \| 'mark', color: 'brand' \| 'ink' \| 'bone', scale, plate?, pixel? })`. `scale: 1` ≈ 151 px высоты. `plate: true` — бетонная подложка с пиксельной тенью (как в меню). `pixel: true` + `variant: 'mark'` — пиксельный знак для ≤ 48 px. |
| SVG-исходники | `src/assets/logo/` | `jedibo-mark.svg` (сетка 7×7 модулей), `jedibo-wordmark.svg`, `jedibo-logo.svg`; цвет — `currentColor`. Трассировка гайда (расхождение ≤ 1 px гайда); если владелец пришлёт вектор — заменить файлы. |
| Пиксельный знак | `render/sprites.ts` | `logoMark(k, color)` — модуль `k` px, сторона `7k`; кэшируется. Используется рубашкой карт и favicon. |
| Фон | `render/background.ts` | `setMood(m)` сбрасывает свои цвета. `setBackgroundPalette({ a, b, c })` — свои цвета; `setBackgroundPalette({ cycle: [[a,b,c], …], period: 45000 })` — плавный цикл по кругу; `setBackgroundPalette(null)` — назад к настроению. Набор цветов для меню «а» подбирает B. |
| Слайдер | `ui/widgets.ts` | `pixelSlider({ value, min, max, step, label, format, onInput, onChange })` — нативный range, `onChange` при отпускании (звук-клик уже внутри). |
| Карта | `ui/card.ts` | `cardEl(id, { scale, faceUp, idle, tilt, shineSafe })`. Блик рисуется канвасом в разрешении карты 52×72 (`drawShine`). `shineSafe: Rect[]` — прямоугольники в пикселях карты, куда блик не ложится (по умолчанию — плашка названия и строка тира иконочной стороны). Для иллюстраций: добавить на `.kcard` класс `illus` — блик станет `soft-light`, мягче. Лицевая сторона может быть `<img>`/canvas во всю карту — передайте свой `shineSafe` под плашку названия. |
| Обломки | `ui/widgets.ts` | `rubbleEl(scale)` — пиктограмма потерянных фигур (вместо «✝»). |
| Цвет с альфой | `render/pixel.ts` | `withAlpha(PAL.x, a)` — для подсветок на канвасе. |

## Свитчер
- Реестр: `src/ui/variants/registry.ts` — `variantOf`, `setVariant`, `screen(id, arg)`, `open(id, arg)`, `cardArtMode`.
  Все переходы идут через `open('menu' | 'modeSelect' | 'chronicle' | 'codex' | 'rules' | 'settings' | 'game', kind)`.
- Хранение: `localStorage['jedibo.ui.v1']`. Адрес: `?ui=b`, `?ui=menu:a,codex:b`, `?cards=illustrated|icons`,
  `?screen=<id>` (стартовый экран — для ссылок на сравнение), вместе с `?theme=light`.
- На `<body>` — `ui-a | ui-b | ui-c` по варианту текущего экрана. Стили: `src/styles/variants/a.css`, `b.css`, `cards.css`, `switcher.css`.
- Плашка «ВИЗУАЛ» — вертикальная вкладка у левого края (внизу), `F2` — показать/скрыть. Смена темы — перезагрузка
  с возвратом на тот же экран (кроме партии). Смена варианта партии — со следующей партии (тост).

## Как устроены варианты
- «а» и «б» одного экрана строятся **одним кодом** (`src/ui/variants/<screen>/v.ts`, параметр `Look`), вид задают
  `a.css` (токены и компоненты A: `.slab`, `.btn`, палитра) и `b.css` (свои токены `--b-*`, два набора по теме).
  Классы компонентов A добавляются только в «а» через `A(v, 'slab')`.
- «в» — экраны A без изменения вида (`src/ui/screens/*`); добавлены только переходы через реестр, кнопка «Летопись»
  в меню и переключатель карт в Колоде.
- Фон: «б» — `setBackgroundStyle('swirl')` (новый стиль шейдера, «пиксель» 8 px) + цвета из `--b-bg-*`;
  «а» в меню — цикл из 4 приглушённых палитр (`--a-cycle-*` в `a.css`, по теме), 160 с на круг. `setMood` сбрасывает стиль.
- Шрифты «б»: Press Start 2P (заголовки, кнопки), Rubik (текст). Pixelify Sans отвергнут: кириллица «С»/«К» с артефактами.
- Меню «а/б» по решению владельца: вместо плитки «Классика» — кнопка «ИГРАТЬ» с треугольником из партии; подложка по
  размеру содержимого.

## Иллюстрации карт
- `scripts/pixelize-cards.py` (Pillow, запуск вручную) → `public/cards/pixel/<cardId>.png`, 48×68, палитра — токены
  `palette.ts`. Таблица кадрирования `CROP` в начале скрипта. Ручной доводки PNG не было.
- `render/cardArt.ts → illusFace(id)`, `preloadIllustrations()`; карта в режиме иллюстраций получает класс `illus`
  (блик мягче, свой `shineSafe`). Режим действует везде, где `cardEl` (колода, рука, оверлей Кармы).

## Летопись и эмблемы
- `src/profile/emblems.ts`: 18 эмблем Классики, `checkEmblems(outcome)` после партии (тосты «Новая эмблема»),
  `chronicleSummary`. Иконки 16×16 — `render/emblemArt.ts` (подложка по тиру + ASCII-глиф, закрытые — тёмный силуэт).
- `MatchRecord` расширен необязательными полями (`ownTurns`, `karmaReceived`, `piecesLost`, `piecesTotal`, `promotions`,
  `cardsPlayed`, `mode`), история — до 40 записей. Статистика считается в `session/match.ts` (`MatchStats`).
- Замены условий: «До круга» — «повысить квадрат до круга» (движок пересоздаёт фигуру при повышении, цепочку
  треугольник→квадрат→круг одной фигуры не отследить). «Безупречная кладка», «Последний камень», «Снос» — только при
  победе уничтожением армии (не за сдачу соперника).
