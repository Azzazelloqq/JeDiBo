# JeDiBo — бот: проект

Новый бот для режима «Против Странника» с уровнями сложности. Текущий жадный бот (`src/ai/bot.ts`) заменяется
целиком. План работ по этапам и оценка — [PLAN.md](PLAN.md).

**Коротко:** ход планируется целиком (до 5 действий) разложением по правилам: «чем закончить ход» (взятие или
нет) + «чем занять остальные очки действия». Каждый вариант хода проверяется дешёвой моделью ответа соперника,
которая опирается на правило «одно взятие за ход». Поиск идёт на отдельной быстрой доске, в браузере — в
Web Worker. Решения по Карме принимаются на настоящем движке. Уровни сложности задаются набором параметров, а не
только глубиной, и калибруются на арене.

---

## 1. Требования

- **Сила.** Сложный уровень уверенно обыгрывает средний (≥75% на арене), средний — лёгкий. Бот доводит
  выигранный эндшпиль до победы (сейчас не умеет, §2.2).
- **Уровни сложности** выбираются перед партией. Слабые уровни ошибаются «по-человечески», а не случайно.
- **Не тормозит интерфейс.** В браузере расчёт идёт в Web Worker; на ход — не дольше бюджета уровня (§8).
- **Честный.** Бот не читает то, чего не видит игрок: порядок колоды `s.deck` и состояние ГСЧ `s.rng` (§9.2).
- **Работает без DOM.** Ядро бота — чистые функции, собирается в `tsconfig.pure.json`; `npm run sim` и арена
  гоняют его в Node синхронно.
- **Воспроизводимость на арене.** При бюджете в узлах (а не в миллисекундах) и фиксированном seed бота партия
  повторяется — нужно для сравнения версий и подстройки весов.

## 2. Что выяснили замерами

Замеры на текущем движке (Node, один поток), 40–100 партий бот против бота.

### 2.1. Стоимость операций

| Операция | Время |
|---|---|
| Клон `GameState` (JSON / `structuredClone`) | 11 / 23 мкс |
| Генерация всех ходов стороны | 10 мкс |
| `isAttacked` для одной клетки | 10 мкс |
| Клон + `dispatch` одного хода | 39 мкс |
| Легальных действий в позиции | 72 в начале, ~54 дальше; максимум ~150 |
| Доля решений по картам (pending) | 1.6% |

Вывод: поиск на движке «как есть» стоит сотни микросекунд на узел (клон + проверки атак для оценки) — это и
делает перебор медленным. Карма по объёму вычислений почти ничего не стоит: решения по картам редки, а действующие
эффекты — это флаги для генерации ходов.

### 2.2. Партии не заканчиваются

| Итог 100 партий | |
|---|---|
| Все фигуры уничтожены | 68 |
| Ничья по правилу «состав не менялся» | 1 |
| **Не закончены за 3000 ходов** | **31** |
| Длина партии, медиана / 90-й процентиль | 97 / 3000+ ходов |

В незаконченных партиях к 300-му ходу на доске остаются **одни круги** (во всех составах, что попали в топ-12): `CCC vs CCCC`,
`CC vs CCC`, даже `C vs CCCCC`. Треугольники и квадраты не умеют ходить назад и рано или поздно повышаются до
кругов, а ловить круг кругами — отдельная задача: дальность 5 во все стороны, и круг-жертва бьёт охотника в ответ
по той же линии. Правило ничьей покрывает только `1×1` и `2×2` с одинаковым составом.

Это главный нюанс проекта, подробнее — §7.1.

## 3. Особенности правил, на которых строится бот

1. **Каждая фигура действует один раз за ход** (`canAct`: `acted`). Ход — это до 5 действий **разными** фигурами.
2. **Взятие завершает ход** (`s.ap = 0`). Значит, за ход возможно **одно взятие**, и взятие всегда — последнее
   действие. Исключение — Блицкриг (одна фигура до 5 действий подряд, но взятие всё равно завершает).
3. **Тихие ходы разных фигур почти всегда переставляемы**: A→B и B→A дают одну позицию. Порядок важен только
   когда одна фигура освобождает клетку или линию для другой.
4. **Треугольники и квадраты не ходят назад** (вперёд / вперёд-вбок). Позиция почти необратима, пока на доске
   есть не только круги.
5. **Повышение**: фигура на последнем ряду соперника снимается и ставится рангом выше в своей стартовой зоне;
   под атакой — повышение откладывается на ход. Это главный «стратегический двигатель» до эндшпиля.
6. **Карма** приходит в начале каждого 7-го своего хода — момент известен заранее обоим. Сама карта — случайная
   из неизвестного остатка колоды.
7. **Выборы по картам** (`pending`) бывают в начале хода (карта получена) и посреди хода (повышение после хода,
   «Свежая кровь»). Иногда выбирает **соперник** (Двойная смерть, Девальвация, Предательство).

Из 2 и 3 следует ключевое упрощение: ответ соперника на мой ход — это прежде всего **его лучшее одно взятие**
(плюс позиционные ходы), а не перебор цепочек из 5 действий.

Модули (`src/ai/`):

| `eval.ts` | Оценка позиции с весами `Weights` (§5). |

| `turn.ts` | Генерация кандидатов на ход целиком (§5). |
| `search.ts` | Отбор кандидатов, углубление по бюджету (узлы или мс). |
| `karma.ts` | Решения по `pending` и удержанным картам на настоящем движке (§7.2), знание об остатке колоды. |
| `endgame.ts` | Эндшпиль из кругов (§7.1). |
| `levels.ts` | Описание уровней сложности (§8). |

`src/ai` не импортирует ничего из `ui`, `render`, `session`; ядро движка — только для решений по картам и
проверок. Случайность бота — свой seeded-ГСЧ, не `Math.random` и не `s.rng`.

## 5. Ход целиком

### 5.1. Кандидаты

Вместо перебора цепочек (луч забивается одинаковыми позициями в разном порядке и выкидывает подготовительные
ходы) ход раскладывается по правилам из §3:

1. **Завершение хода** — одно из:
   - прямое взятие (кандидатов обычно 0–10);
   - взятие после 1–2 **подготовительных** ходов: фигура подходит на атакующую клетку или освобождает линию
     другой фигуре. Ищется целенаправленно от цели: «какие мои фигуры могут атаковать эту клетку после хода
     ещё одной фигуры»;
   - без взятия.
2. **Тихие ходы** на оставшиеся очки действия — жадно по приросту оценки с пересчётом после каждого. Каждой фигуре
   — не больше одного действия, взятие всегда последним. Ход, который ухудшает позицию (оголяет фигуру), не
   делается: очки действия тратить не обязательно, кроме первого действия.
3. Небольшой лучевой поиск поверх жадного выбора (ширина 2–4) **с отсевом одинаковых позиций по хэшу** — чтобы
   не терять варианты, где первый тихий ход выглядит хуже, но открывает лучший второй.

Итог: 5–30 кандидатов «полный ход» на позицию.

### 5.2. Оценка кандидата

`score(ход) = eval(после хода) − лучший ответ соперника (§6) + мой лучший ответный удар`.

На глубоких уровнях `search.ts` для 3–5 лучших кандидатов строит **полный ход соперника** тем же генератором и
снова оценивает. Это углубление по бюджету: пока есть время, добавляем полуходы.

### 5.3. Оценка позиции

Начальные веса задаются вручную, потом подстраиваются на арене (этап 7).

- Материал: треугольник 1, квадрат 3, круг 5 (значения подстраиваются).
- Продвижение треугольников и квадратов к последнему ряду (нелинейно: последние 2 ряда — дороже), «проходные»
  фигуры, которых никто не может остановить.
- Висящие фигуры: атакованы и не защищены — штраф, с учётом того, что соперник возьмёт только одну.
- Защищённость и угрозы: сколько своих фигур под боем «сквозь блокеры».
- Подвижность кругов и квадратов, контроль центра.
- Отложенное повышение (`promoteNextTurn`): почти готовая новая фигура.
- Карма: известный момент следующей карты у себя и у соперника и остаток колоды (§7.2) — например, пока не
  вышли обе «Линии смерти», дорого держать много фигур в одном столбце.
- Эндшпиль: при перевесе — сближение с фигурами соперника и зажим к краю (§7.1).

## 6. Модель ответа соперника

Соперник за ход может переставить до 4 фигур и одной взять. Значит, фигура в опасности, если её атакует фигура
соперника **с учётом того, что его собственные блокирующие фигуры могут уйти с линии** первыми (атака «сквозь свои
фигуры», одна прослойка). Мои фигуры на линии остаются блоками.

- **Лучшее взятие соперника** = максимум по моим атакованным фигурам с учётом размена: если после взятия я беру
  в ответ, засчитывается разница. Это упрощённая оценка размена (SEE) на 1–2 обмена, которых хватает: за ход
  только одно взятие.
- **Угроза повышения**: фигура соперника, которая за его ход дойдёт до последнего ряда не под атакой.
- **Известная Карма соперника**: если у соперника на руках карта или следующий его ход — 7-й, оценка не меняется
  (карта неизвестна), но удержанная «Бессмертие» учитывается как возврат последней потерянной фигуры.

Стоимость на быстрой доске — одна генерация атак, единицы микросекунд (оценка; на движке «как есть» было бы
~10 мкс × число фигур).

## 7. Эндшпиль и Карма

### 7.1. Эндшпиль из кругов

Без отдельной логики бот играет эндшпиль из кругов бесконечно (§2.2). Тут два вопроса — дизайна и техники.

**Вопрос дизайна (решает автор игры):** выигрывается ли такой эндшпиль вообще при точной защите? Если `CC vs C` —
ничья при правильной игре, никакой бот партию не закончит, и нужно правило. Варианты:
- ограничение «N своих ходов без взятия и повышения → ничья» (как правило 50 ходов в шахматах);
- то же, но победа по материалу;
- расширение текущего правила ничьей на любые составы из одних кругов.

**Техника:**
- `endgame.ts`: при перевесе — эвристика «зажать»: держать свои круги парами (один защищает другого, тогда
  размен выгоден), сужать безопасные клетки жертвы, гнать к краю/углу. Безопасные клетки жертвы считаются
  быстро: доска маленькая.
- **Таблица эндшпилей** (по желанию, этап 8): для `CC vs C` полный перебор позиций в Node — 144³ ≈ 3 млн позиций,
  посчитать офлайн и положить в сборку как бинарную таблицу (порядка сотен КБ после сжатия; точный размер —
  после замера). Заодно даст ответ на вопрос дизайна: выигрывается ли `CC vs C`. Для 4+ фигур таблица уже не
  влезает в веб, только эвристика.

### 7.2. Карма

| Карта | Кто выбирает | Как решает бот |
|---|---|---|
| Бессмертие (держится) | я | Держать, пока в этом Периоде не погибнет ценная фигура; сыграть, если Период кончается. |
| Прыгун (держится) | я | Сыграть сразу: эффект длится тот же Период, держать нет смысла. |
| Воскрешение | я | Самая ценная фигура с кладбища; клетка — перебором по оценке. |
| Подарок, Свежая кровь, повышение | я | Клетка постановки — перебором по оценке (безопасность, близость к фронту). |
| Двойная смерть врага, Шпион | я | Перебор: какая фигура соперника важнее всего для его позиции (а не просто самая дорогая). |
| Двойная смерть, Девальвация | соперник выбирает **мои** фигуры | Бот в роли соперника выбирает фигуры, потеря или понижение которых сильнее всего ухудшит позицию владельца. |
| Карьерный лифт вверх/вниз | я | Перебор пар по оценке. |
| Отступление | я, можно пропустить | Отводить только атакованные фигуры, остальное — пропуск. |
| Защитный барьер | я | Перекрыть линию атаки соперника на мою ценную фигуру или его путь к повышению. |
| Предательство | соперник двигает **мои** фигуры | Бот в роли соперника: 3 хода чужими фигурами под свой удар, жадно с пересчётом. |
| Блицкриг | — (эффект) | Отдельный генератор: одна фигура, цепочка до 5 действий, поиск в глубину с отсечением. |
| Депрессия, Тихоход, Круговая защита | — (эффект) | Учтены в генерации ходов быстрой доски. |
| Линия смерти, Пропуск хода, Смена поля | — | Решать нечего. |

Решения по картам принимаются на **настоящем движке**: клон + `dispatch(choose)` + оценка для каждого варианта.
Вариантов ≤150, это ~6 мс: дешевле и надёжнее, чем учить быструю доску всем картам. Многошаговые выборы (две
фигуры, три отступления) — жадно по шагам.

Остаток колоды бот считает по открытой информации: 34 карты минус сыгранные и сброшенные. Состав колоды матча
(21 из 34) и её порядок бот не знает — как и игрок.

## 8. Уровни сложности

Уровень — это набор параметров, а не только глубина. Слабый бот, который «просто думает меньше», ошибается
неестественно; бот, который не видит дальних угроз и иногда выбирает второй по силе ход, похож на живого новичка.

| Параметр | Новичок | Любитель | Мастер | Гроссмейстер |
|---|---|---|---|---|
| Угрозы «сквозь блокеры» | нет | да | да | да |
| Ответ соперника | не учитывает | лучшее взятие | + размен | + полный ход соперника |
| Подготовительные ходы к взятию | нет | 1 ход | 2 хода | 2 хода |
| Выбор среди кандидатов | случайный из лучших (высокая температура) | слабый шум | почти лучший | лучший |
| «Зевок» (пропустить угрозу) | ~15% | ~5% | 0 | 0 |
| Карма | сразу и просто | по оценке | по оценке | по оценке + остаток колоды |
| Эндшпиль | без логики | эвристика | эвристика | эвристика + таблица |
| Бюджет на ход | ~20 мс | ~80 мс | ~250 мс | ~600 мс |
| Рейтинг (для Эло профиля) | калибруется | калибруется | калибруется | калибруется |

Рейтинг каждого уровня определяется на арене (Эло между уровнями, привязка Новичка к ~800). Сейчас бот имеет
фиксированный рейтинг 1000 (`recordMatch(..., oppRating = 1000)`), с уровнями он берётся из `levels.ts`.

В UI: выбор уровня перед партией против Странника (плитка в меню → выбор уровня), уровень запоминается в профиле.

## 9. Интеграция

### 9.1. Match и воркер

Сейчас `MatchConfig.botAct` синхронный и возвращает одно действие. Новый вход:

- `agent.planTurn(...)` считает план на весь ход один раз и отдаёт действия по одному (анимация каждого действия
  сохраняется). План пересчитывается, если состояние разошлось с ожидаемым: появился `pending` (повышение,
  Свежая кровь), фигура не там, действие отклонено.
- В браузере `BotClient` отправляет состояние в воркер (`postMessage` со структурным клоном, ~20 мкс) и получает
  план. `Match.driveBots` ждёт промис, проверяя, что ход всё ещё того же игрока и состояние не менялось.
  Задержка «на подумать» = max(время расчёта, `botDelay`).
- В Node (`sim`, `netsim`, арена) — тот же `planTurn` синхронно.
- Воркер — один. Несколько воркеров (по ядрам, деление кандидатов) — только если на Гроссмейстере не хватит
  бюджета; SharedArrayBuffer не нужен.

### 9.2. Честность и ГСЧ

Будущие карты и столбец «Линии смерти» берутся из `s.rng` и `s.deck`, которые лежат в `GameState`. Значит,
любой, у кого есть состояние, может **точно предсказать** следующие карты, просто прогнав ГСЧ вперёд. Бот этого
делать не должен: в поиске и решениях по картам он не трогает `s.deck` и `s.rng` (проверка — тестом: подмена
`s.deck`/`s.rng` не меняет план бота).

Побочный вывод вне бота: в сетевой игре оба клиента держат полное состояние, и игрок с консолью разработчика
может знать свои и чужие будущие карты. Это вопрос к сетевому проекту, не к боту.

## 10. Проверка

- `scripts/arena.ts` — `npm run arena -- A B 200`: два бота (уровни или версии) с обменом сторонами, винрейт с
  доверительным интервалом, средняя длина партии, доля незаконченных, среднее и максимальное время на ход.
- Сверка быстрой доски с движком: на позициях из `sim` генерация ходов `FastBoard` совпадает с `targetsOf` для
  всех фигур, включая эффекты Кармы.
- Честность: тест из §9.2.
- `npm run sim` и `npm run netsim` переходят на новый бот и проходят как раньше.

## 11. Риски и открытые вопросы

| Риск | Что делаем |
|---|---|
| Эндшпиль из кругов не выигрывается при точной защите | Решение автора игры по правилу (§7.1); таблица `CC vs C` даст ответ. |
| Быстрая доска расходится с движком на редких эффектах | Сверочный тест по тысячам позиций; решения по картам — на движке. |
| Блицкриг ломает «одна фигура — одно действие» | Отдельный генератор (§7.2). |
| На слабых устройствах не хватает бюджета | Бюджет по времени + углубление: бот всегда возвращает лучший найденный ход. |
| Подстройка весов долгая | SPSA в Node на нескольких процессах, бюджет в узлах; начать с ручных весов. |
| Слабые уровни выглядят «рандомными» | Слабость через пропуск угроз и температуру, а не через случайный ход. |
