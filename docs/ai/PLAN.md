# JeDiBo — бот: план реализации

Проект и обоснования — [README.md](README.md). Текущий жадный бот (`src/ai/bot.ts`) заменяется целиком; до
этапа 6 он остаётся в игре и служит точкой отсчёта на арене. Коммиты небольшие, на русском. После каждого этапа:
`npm run build`, `npm run sim -- 200`, арена против предыдущей версии.

Оценки — в рабочих днях одного разработчика с ассистентом, как в сетевом плане. Самые неопределённые этапы —
5 (эндшпиль) и 8 (подстройка весов): они зависят от того, что покажет арена.

---

## Решения до старта

- [ ] **Правило для бесконечного эндшпиля** (README §7.1). Без него часть партий не закончится даже у сильного
      бота. Варианты: «N своих ходов без взятия и повышения → ничья», то же с победой по материалу, расширение
      правила ничьей на любые составы из кругов. Можно отложить до этапа 5 и решить по данным арены и таблицы
      `CC vs C`.
- [ ] Число и названия уровней (в проекте — 4: Новичок, Любитель, Мастер, Гроссмейстер). Один «Странник» с
      уровнями или разные имена ботов.

## Этап 0. Арена (≈0.5 дня)

- [ ] Интерфейс бота: `planTurn(state, me, level, rng) → Action[]` и адаптер старого бота под него.
- [ ] Свой seeded-ГСЧ бота, бюджет в узлах (для воспроизводимости) и в миллисекундах.
- [ ] `scripts/arena.ts`, `npm run arena -- A B 200`: смена сторон, винрейт с доверительным интервалом, длина
      партии, доля незаконченных (лимит 1000 ходов), время на ход (среднее, 95-й процентиль, максимум).

**Готово, когда:** старый бот против себя даёт ~50% и те же ~31% незаконченных партий, что в замерах.

## Этап 1. Быстрая доска (≈2 дня)

- [ ] `src/ai/board.ts`: `FastBoard.fromState(s)`, доска `Int8Array`, фигуры в типизированных массивах,
      генерация ходов и атак, `make/unmake`, флаги `acted` и очки действия.
- [ ] Эффекты Кармы в генерации: Депрессия, Тихоход, Круговая защита, Прыгун, Барьер; Блицкриг — флаг для
      отдельного генератора.
- [ ] Атаки «сквозь свои фигуры» (одна прослойка) для модели ответа.
- [ ] Сверочный тест: на позициях из `sim` (включая партии с эффектами) ходы `FastBoard` совпадают с
      `targetsOf` для каждой фигуры; `make/unmake` возвращает исходную позицию (по хэшу).
- [ ] Замер: генерация ходов и проверка атак против нынешних 10 мкс.

**Готово, когда:** сверка проходит на 10 000+ позиций, генерация ходов быстрее движка хотя бы в 10 раз.

## Этап 2. Оценка и модель ответа (≈1.5 дня)

- [ ] `src/ai/eval.ts`: материал, продвижение, проходные фигуры, висящие и защищённые фигуры, подвижность,
      отложенное повышение. Веса — объект `Weights`.
- [ ] `src/ai/reply.ts`: лучшее взятие соперника с учётом отводимых блокеров, размен на 1–2 обмена, угроза
      повышения.
- [ ] Набор тестовых позиций «очевидный правильный ход» (висящая фигура, ловушка с разменом, открытая линия) —
      бот на один ход решает их.

**Готово, когда:** тестовые позиции решаются; оценка одной позиции — единицы микросекунд.

## Этап 3. Ход целиком и поиск (≈2.5 дня)

- [ ] `src/ai/turn.ts`: кандидаты-завершения (прямые взятия, взятия после 1–2 подготовительных ходов, без
      взятия), жадные тихие ходы, узкий луч с отсевом одинаковых позиций по хэшу.
- [ ] `src/ai/search.ts`: оценка кандидатов через модель ответа, углубление на полный ход соперника для лучших,
      остановка по бюджету с лучшим найденным ходом.
- [ ] `src/ai/agent.ts`: план на ход, выдача действий по одному, пересчёт при `pending` или расхождении.
- [ ] Повышение посреди хода: выбор клетки через `karma.ts` (пока — простая эвристика).

**Готово, когда:** на арене новый бот (уровень «Мастер», 250 мс) выигрывает у старого ≥90% партий,
95-й процентиль времени на ход в Node — в пределах бюджета.

## Этап 4. Карма (≈1.5 дня)

- [ ] `src/ai/karma.ts`: решения по всем `pending` на движке (клон + `dispatch` + оценка), включая выборы за
      соперника (Двойная смерть, Девальвация, Предательство) — по таблице README §7.2.
- [ ] Удержанные карты: Прыгун — сразу, Бессмертие — по ситуации и до конца Периода.
- [ ] Генератор Блицкрига: цепочка одной фигуры до 5 действий, поиск в глубину с отсечением по оценке.
- [ ] Остаток колоды по открытой информации; учёт в оценке (Линия смерти и столбцы).
- [ ] Тест честности: подмена `s.deck` и `s.rng` не меняет план бота.

**Готово, когда:** арена с Кармой против версии этапа 3 — не хуже, на позициях с картами решения разумны
(проверка глазами на 20–30 случаях).

## Этап 5. Эндшпиль (≈1.5–3 дня, неопределённость)

- [ ] Замер: какие составы остаются в незаконченных партиях у нового бота.
- [ ] `src/ai/endgame.ts`: при перевесе — пары кругов с взаимной защитой, сужение безопасных клеток жертвы,
      оттеснение к краю.
- [ ] По итогам — решение по правилу для бесконечного эндшпиля (раздел «Решения до старта») и его
      реализация в движке, если нужно (затронет `checkDraw` и сетевые тесты).

**Готово, когда:** «Мастер» против «Мастера» — незаконченных партий меньше 2% (с правилом или без).

## Этап 6. Браузер (≈1 день)

- [ ] `src/ai/botWorker.ts` + `botClient.ts`: воркер через `new Worker(new URL(...), { type: 'module' })`,
      асинхронный клиент.
- [ ] `Match.driveBots` с асинхронным ботом: проверка, что ход и состояние не изменились, задержка =
      max(расчёт, `botDelay`).
- [ ] Перевод `sim`, `netsim`, `devtools` на новый бот; удаление `src/ai/bot.ts`.
- [ ] Проверка в браузере: интерфейс не подвисает во время хода бота, на телефоне время на ход в бюджете.

**Готово, когда:** партия против бота в браузере идёт плавно, `sim` и `netsim` проходят.

## Этап 7. Уровни сложности (≈1.5 дня)

- [ ] `src/ai/levels.ts`: параметры уровней (README §8): угрозы сквозь блокеры, глубина ответа, подготовка
      взятий, температура выбора, «зевки», Карма, эндшпиль, бюджет.
- [ ] Калибровка на арене: соседние уровни ~75–85% в пользу старшего; рейтинги уровней по Эло.
- [ ] UI: выбор уровня перед партией против бота, запоминание в профиле, рейтинг уровня в `recordMatch`.

**Готово, когда:** арена показывает строгий порядок уровней, в меню можно выбрать уровень.

## Этап 8. Подстройка весов (≈1–2 дня + машинное время)

- [ ] `scripts/tune.ts`: SPSA по `Weights`, партии на нескольких процессах Node, бюджет в узлах.
- [ ] Новые веса принимаются, только если арена против прежних даёт значимый плюс.
- [ ] После подстройки — повторная калибровка уровней (этап 7).

**Готово, когда:** подстроенные веса выигрывают у ручных значимо (≥55% на 400+ партиях) или подстройка не даёт
прироста и это зафиксировано.

## Этап 9 (по желанию). Таблица эндшпиля `CC vs C` (≈2–3 дня)

- [ ] Офлайн-перебор в Node с учётом хода целиком (каждый круг — одно действие) и симметрий доски.
- [ ] Ответ на вопрос дизайна: выигрывается ли `CC vs C` и за сколько ходов.
- [ ] Компактный бинарный формат, загрузка в воркер; размер в сборке — по замеру.

**Готово, когда:** Гроссмейстер играет `CC vs C` по таблице без ошибок.

## Итог по оценке

| Часть | Дни |
|---|---|
| Этапы 0–4: сильный бот без эндшпиля | ≈8 |
| Этап 5: эндшпиль | 1.5–3 |
| Этапы 6–7: браузер и уровни | ≈2.5 |
| Этап 8: подстройка весов | 1–2 |
| **Всего** | **≈13–15.5** |
| Этап 9 (по желанию) | +2–3 |

Первая играбельная версия (бот заметно сильнее старого, в браузере, без уровней) — после этапов 0–3 и 6,
≈7.5 дня. Уровни можно выпустить сразу после неё с ручной калибровкой, а подстройку и эндшпиль — следом.
