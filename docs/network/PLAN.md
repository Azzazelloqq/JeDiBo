# JeDiBo — сетевая игра: план реализации

Проект и обоснования — [README.md](README.md). Вариант v1 — **хост на клиенте** (WebRTC через PeerJS).
Вся работа — в ветке `network` (от `redesign`), коммиты небольшие, на русском. После каждого этапа:
`npm run build`, `npm run sim -- 200` (офлайн-режимы не сломаны) и проверка этапа.

Этапы 0–3 не трогают UI. Этап 4 — минимальные экраны, чтобы начать тестировать по-настоящему, до редизайна.
Финальный вид экранов (этап 6) — после вливания задачи A в `redesign`.

**Готово, когда:** `netsim` 100 партий без рассинхронов и исключений, все «плохие» сценарии отклоняются.

Стресс-режим: `SC=drop,restore STRESS=1 npm run netsim -- 100` — обрывы каждые 5–55 мс. Найдено и исправлено им:
`start` с длинным логом не проходил лимит 8 КБ (лимит теперь только для сообщений клиента);
двойное обязательство расстановки при повторном `place()`; запоздавший `hello` старого соединения
отнимал место у нового (теперь у `hello` есть номер попытки `n`).

- [x] Зависимость `peerjs` (точная версия).

- [x] `GuestLink` (гость): подключение по коду, heartbeat, переподключение с паузой до 2 с, статус с

- [x] Хост сам играет через `LoopbackTransport` к своей `HostRoom`.
- [x] `start` с полным логом длинной партии — сотни КБ: проверить, что PeerJS-канал передаёт такие сообщения
      (при необходимости — сжатие лога или нарезка на куски).
- [x] Конфиг ICE-серверов в одном месте (`src/net/peer.ts`), по умолчанию — STUN.
- [x] Отладка: `__net` в консоли (статус, лог, хэши), лог сообщений в dev-сборке.

**Готово, когда:** два окна на одном ПК (обычное + приватное) играют партию через `npm run dev`
(пока — через консоль `__net`/временную кнопку).

Проверено (две вкладки встроенного браузера, публичный брокер PeerJS, боты через `__net.bots()`):
вход гостя — 0,4 с; обрыв канала гостя → возврат 0,7 с; перезагрузка вкладки хоста → комната поднимается из
`sessionStorage` за 0,1 с после загрузки, гость возвращается за 0,8 с; `start` на 17 КБ (358 действий) прошёл;
хэши обеих вкладок совпадают до конца партии; неверный код → «комната не найдена» за ~14 с.
Найдено и исправлено: не открывшийся канал PeerJS закрывает без события `close` (гость зависал в
«подключении»); повторный `hello` с другим именем менял имена партии в `start` → вечный рассинхрон (имена
теперь фиксируются при старте, повторный рассинхрон ограничен 3 попытками); брокер не всегда сообщает
`peer-unavailable` (отсутствие хоста определяется по неотвеченному предложению).
Не проверено: две разные сети и строгий NAT — это этап 4 с людьми.

### Чек-лист тест-сессии с людьми

Запуск: `npm run dev:lan` (HTTPS с самоподписанным сертификатом — без HTTPS браузер не даёт `crypto.subtle`,
и на чужом устройстве по `http://192.168…` сеть не заработает). Оба игрока открывают адрес из строки `Network:`
(в одной сети) и соглашаются с предупреждением о сертификате. Для разных сетей — опубликованная сборка (этап 7). Каждый пункт — отметить результат и время.

1. ПК ↔ ПК, одна сеть: создать комнату, войти по ссылке, сыграть до конца, реванш.
2. ПК ↔ телефон по мобильному интернету (разные сети): соединилось ли вообще; если нет — какой отказ показан.
3. Перезагрузка вкладки гостя посреди партии; затем хоста. Сколько секунд до возврата.
4. Гость сворачивает браузер на телефоне на 5–10 с и возвращается.
5. Хост закрывает вкладку: через сколько секунд гость увидел отсчёт и итог (в браузерном тесте — ~12 с до отсчёта).
6. Вход по неверному коду; вход третьим в занятую комнату.
7. Карты Кармы, где выбирает соперник («Двойная смерть», «Девальвация», «Предательство»): подсказка «… выбирает».
8. Таймер хода у обоих совпадает (±1 с), таймаут хода срабатывает.

## Потом (по результатам тестов)

- TURN-сервер в списке ICE — если много несоединившихся пар.
- Свой `peerjs-server` — если публичный брокер нестабилен.
- Перенос `Room` на Cloudflare Durable Object + `WsTransport` (README §11) — если мешают вылеты хоста или нужна честность.
- Поиск случайного соперника, зрители, чат/эмоции, скрытие колоды Кармы.

## Риски

| Риск | Что делаем |
|---|---|
| Не соединяются пары за строгим NAT | понятная ошибка `failed`, статистика на тестах, TURN по результатам |
| Публичный PeerJS-брокер недоступен | свой брокер — один процесс, клиент меняет только URL |
| Хост закрыл/свернул вкладку (особенно телефон) | `sessionStorage` + подъём комнаты, ABANDON, совет «хостить с ПК» |
| Окно переподключения 15 с короткое: брокер может не сразу отдать peer id после перезагрузки хоста | замерить на тестах; при необходимости — новый peer id с суффиксом поколения, гость перебирает `jedibo-<код>-<n>` |
| Скрытая недетерминированность в `core` | полный `stateHash` + `netsim`; правило «в core нет Math.random/Date» |
| Жульничество хоста | commit-reveal для seed и расстановки, гость проверяет всё своим `dispatch`; часы и колода — на доверии |
| Редизайн параллельно меняет `game.ts` | этап 4 — минимальные правки; этап 6 — после вливания A |
