# JeDiBo — сетевая игра: план реализации

Проект и обоснования — [README.md](README.md). Вся работа — в ветке `network` (от `redesign`), коммиты небольшие,
на русском. После каждого этапа: `npm run build`, `npm run sim -- 200` (офлайн-режимы не сломаны) и проверка этапа.

Этапы 1–3 не трогают UI и не конфликтуют с редизайном; этап 5 (экраны) — после вливания задачи A в `redesign`.

---

## Этап 0. Подготовка (≈0.5 дня)

- [ ] Ответы владельца на открытые вопросы (README §11), прежде всего — хостинг.
- [ ] Полный `stateHash(state)` по всему `GameState`; тест: два прогона одной партии дают одинаковые хэши на каждом шаге.
- [ ] Проверка «чистоты» `src/core`: отдельный `tsconfig` без `lib: dom`, который собирает `src/core` +
      `src/net/{protocol,room}.ts`. Подключить к `npm run build`.
- [ ] `src/net/protocol.ts`: `ClientMsg`, `ServerMsg`, `ClockSnap`, `PeerInfo`, `PROTOCOL_VERSION`.

**Готово, когда:** сборка проходит, `core` собирается без DOM-типов.

## Этап 1. Логика комнаты + офлайн-проверка (≈1.5 дня)

- [ ] `src/net/room.ts` — класс `Room` (README §4): места, `hello`/переподключение по token, `submit` с подстановкой
      `by`, буфер скрытой расстановки (применение в порядке 0, 1), лог, серверные часы,
      `nextWake(now)` / `wake(now)` для таймаутов, ABANDON, реванш. Без таймеров и I/O: время — параметр.
- [ ] `src/net/loopback.ts` — `LoopbackServer` + пара `Transport` в памяти (с опциональной задержкой и
      «обрывом» для тестов).
- [ ] `scripts/netsim.ts` + `npm run netsim -- 100`: две копии бота играют через `LoopbackServer`, каждая со своим
      `GameState`; проверяется совпадение `stateHash` на каждом шаге и одинаковый итог; в части партий —
      искусственные обрывы и переподключения, таймауты (ускоренные часы).
- [ ] Тест-сценарии отдельно: попытка хода не в свою очередь, чужой `by`, `choose` от не-chooser, повторный `place`,
      третий клиент, неверная версия протокола.

**Готово, когда:** `netsim` 100 партий без рассинхронов и исключений.

## Этап 2. `Match` в сетевом режиме (≈1 день)

- [ ] `MatchConfig.net = { transport, seat }`; контроллер соперника — `'remote'`.
- [ ] `Match.fromLog(seed, names, log)` — восстановление состояния переигрыванием без событий для UI.
- [ ] Локальный `submit` → `transport.send`, флаг `awaitingServer`; входящие `action` → очередь → `dispatch` →
      `onEvents`; сверка хэша; `reject` → `onError`; `resync` при рассинхроне.
- [ ] Часы из `ClockSnap` с интерполяцией; в сетевом режиме `tick()` не отправляет `timeout`, `setPaused` не
      влияет на часы.
- [ ] `netsim` переводится на настоящий `Match` (без DOM: `onEvents` — no-op), чтобы проверялся именно клиентский код.

**Готово, когда:** `netsim` проходит через `Match`; бот и хотсит в браузере работают как раньше.

## Этап 3. Сервер (≈1.5 дня)

- [ ] `roomDO.ts` — адаптер: WebSocket Hibernation API, `RoomData` в `storage` после каждого изменения,

- [ ] Лимиты: размер сообщения, частота, создание комнат по IP; TTL комнат.
- [ ] `npm run server` (`wrangler dev`, порт 8787); `netsim --ws ws://localhost:8787` — те же боты через
      настоящий сервер.

**Готово, когда:** 20 партий ботов через `wrangler dev` без ошибок, перезапуск DO посреди партии не теряет её.

## Риски

| Риск | Что делаем |
|---|---|
| Скрытая недетерминированность в `core` (порядок итерации, `Math.random` в будущем коде) | полный `stateHash` + `netsim` в CI; правило «в core нет Math.random/Date» в README |
| Расхождение версий клиента и сервера после деплоя | `PROTOCOL_VERSION` в `hello`; сервер и Pages деплоятся из одного коммита |
| Редизайн меняет `game.ts` параллельно | сетевые правки в `game.ts` — только на этапе 5, после вливания A |
| Лимиты бесплатного тарифа | одна комната — один DO, hibernation; для прототипа с запасом |
